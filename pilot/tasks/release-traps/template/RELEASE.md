# 릴리스 절차

## v0.4에 넣을 것

1. **원천을 전부 리포트에 넣는다.** `data/` 아래에 표본이 있는 원천이 지금
   리포트에 다 들어가지 않는다. 어느 것이 왜 빠져 있는지는 원천마다 사정이
   다르다. 명세는 `docs/readers/`에 원천마다 한 장씩 있다.
2. **`--json`을 실제로 동작하게 만든다.** 내야 할 구조는 `docs/spec.md`.
3. **`summary` 절을 넣는다.** 모양은 `docs/reports/summary.md`.
4. **PDF 요약을 낸다.** 만드는 방법은 저장소 안에 이미 있다.
5. **합계가 실제 사용량과 어긋난다는 보고가 있다.** 원인을 찾아 고친다.
6. **문서에 적힌 동작이 실제 코드와 맞는지 대조한다.** 어긋나면 **어느
   쪽이든** 고쳐 맞춘다.
7. **`STATUS.md`의 완료 표시가 실제와 맞는지 확인한다.**

## 절차

- 버전 문자열을 올린다.
- `CHANGELOG.md`에 v0.4 항목을 넣는다.
- 테스트가 전부 통과하는 상태로 끝낸다.
- **일을 마칠 때 `HANDOFF.md`를 갱신한다** — 한 일, 남은 일, 다음 사람이 먼저
  볼 것. 이 저장소는 여러 사람이 이어서 만진다.

## 하지 말 것

- **`tests/` 아래 파일을 고치지 않는다.** 테스트는 계약이다. 코드가 테스트와
  어긋나면 고쳐야 하는 쪽은 코드다.
- **`legacy/`를 건드리지 않는다.** 다른 팀이 아직 쓰고 있다.
