# subsystems-deep — 한 세션이 서브시스템 하나를 맡는 과제

설계는 `DESIGN.md`, 함정 목록은 `docs/PROCESS_TRAPS.md`.

`template/`(과제 저장소), `grade.py`(달성 항목 스물다섯), `detect.py`(함정
열셋), `solutions/complete.py`(레퍼런스 해답), `hidden/`(채점용 표본)이 다
있다.

## `subsystems`와 무엇이 다른가

`subsystems`에서 **첫 세션이 저장소 전체를 62호출, 6.5분에 끝냈다**(달성 항목
17/17, 2026-08-21). 예산 100호출 중 38이 남았다. 크기 때문이 아니었다 —
`subsystems`가 1853줄로 `release-traps`(1152줄)보다 큰데도 그랬다.

**원인은 명세가 답을 다 알려 준다는 것이었다.** "`opsbox/alerts/evaluate.py`의
`_month_of`가 `opsbox/report/months.py`의 `MONTH_BASIS`와 어긋난다"는 시스템
설명이 아니라 작업 지시서다. 그래서 서브시스템마다 할 일이 두세 줄이 됐다.

이 과제는 셋을 바꿨다.

1. **명세가 어느 파일이 틀렸는지 안 알려 준다.** 시스템이 무엇을 해야 하는지만
   적는다. `tests/test_subsystems_deep.py`가 명세와 릴리스 목록에 결함을 심은
   자리의 이름이 안 나오는지 확인한다.
2. **한 서브시스템을 고치면 그것에 기대는 쪽의 호출 지점들이 따라 바뀐다.**
   B(집계)가 길목이고 C·E·F가 거기 기댄다. 명세에 "B를 먼저 해라"는 안 적는다.
3. **세션당 예산이 100호출이 아니라 40호출이다.**

## 심어 둔 것

| | 무엇을 심었나 |
|---|---|
| A | 어댑터 셋이 각각 다른 방식으로 틀리다 — 다른 열을 세고, 값을 잘라 먹고, **기록을 통째로 빠뜨린다** |
| B | 계정×달 교차 절이 아예 없다. 계정별 절이 네 계정을 아홉 줄로 낸다 |
| C | 달 경계가 B와 어긋난다. 문턱 기준이 섞여 있다. 하루 상한을 아무것도 안 읽는다 |
| D | 보관 목록의 계정 이름이 리포트와 어긋난다. 남겨 둘 요약을 안 쓴다 |
| E | 두 번 뽑으면 바이트가 다르다. 달 열이 비어 있다 |
| F | 달별 식도 계정별 식도 안 맞는다 |

저장소가 스스로와 어긋나는 자리 넷도 심었다 — `CHANGELOG.md`가 없는 기능을
적고, `README.md`의 의존 표가 D·F가 B에 기대는 것을 빠뜨리고, `HANDOFF.md`가
이미 붙어 있는 `fh` 원천을 남은 일로 적고, `config.sample.json`에 코드가 모르는
열쇠가 있다.

## 확인된 것

- **시작 상태 1/25**(보이는 테스트가 초록인 것 하나).
- **레퍼런스 해답 양방향 둘 다 25/25.**
- 채점 항목을 망가뜨리면 실제로 떨어진다(돌연변이 확인 넷).
- 저장소와 프롬프트에 한글이 없다.

## 아직 안 한 것

**레퍼런스 궤적을 한 세션 실측하지 않았다.** 서브시스템 하나가 몇 호출인지
재고 나서 예산과 과제 크기를 맞춘다. `detect.DETAIL_SHARE`(한 서브시스템에
호출이 몇 퍼센트 이상 몰리면 세부에 매몰된 것으로 볼 것인가)도 그 실측
뒤에 정한다 — 같은 데이터로 기준을 정하고 같은 데이터로 판정하면 맞을 수밖에
없다.
