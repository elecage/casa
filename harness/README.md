# 세션 하네스 — 우리 자신의 세션에 거는 가드레일

`hooks/`와 헷갈리지 말 것. 둘은 목적이 반대다.

| | `hooks/` | `harness/` (이 디렉토리) |
|---|---|---|
| 대상 | **연구 대상 세션** (러너가 격리 디렉토리에서 돌리는 것) | **우리 개발 세션** (이 저장소에서 작업하는 세션) |
| 목적 | 계측 — 규칙 위반과 행동을 기록·측정한다 | 강제 — 방향이 틀어지는 것을 막는다 |
| 배포 | CASA 도구의 일부로 사용자에게 나간다 | 이 저장소 내부용 |

## 왜 만들었나

이 프로젝트의 규칙은 이미 `CLAUDE.md`에 글로 적혀 있었다. 그런데:

- "작업 상태가 바뀌면 같은 커밋에서 STATUS.md를 갱신한다"는 규칙이 있었지만,
  `results/main2/ml-shift-sonnet`의 7세션이 3주 넘게 기록되지 않은 채 남아
  있었고 다음 세션이 **우연히** 발견했다.
- 유저가 설계 문제를 지적했는데 한 세션 안에서 **세 번 연속** 기존 설계의
  측정 결과로 답했다.
- 방향을 두 번 틀었는데 두 번 다 대체 과제가 "함수 하나 구현"으로 돌아갔다.

이 프로젝트가 스스로 내놓은 원칙이 답이다 — **"강제는 코드로, 프롬프트로
하지 않는다. 프롬프트 규칙은 여기서 측정 대상이지 메커니즘이 아니다."**
그 원칙을 연구 대상에만 적용하고 우리 자신에게는 적용하지 않았던 것을
바로잡는다.

## 네 층

| 층 | 파일 | 언제 도는가 | 막는 것 |
|---|---|---|---|
| 시작 앵커 | `session_start.py` | 세션 시작 | 목표·미해결 문제·잠금 상태를 컨텍스트에 강제 주입 (읽기를 기대하지 않는다) |
| 수집 잠금 | `collection_guard.py` | 도구 호출 전 | 설계 문제가 열린 동안 `pilot/run_sessions.py` **실행** 차단 |
| 기록 누락 | `check_records.py` | 커밋 전 | 코드 변경에 STATUS.md 누락 / STATUS.md가 언급 안 하는 수집 배치 |
| 새 과제 검문 | `check_task_design.py` | 커밋 전 | 설계 루브릭(`TASK_DESIGN_RUBRIC.md`) 미작성 과제 |
| 보고 규율 | `report_check.py` | 세션 종료 시 | 내부 약어·정의 없는 통계 용어로 끝나는 보고 (세션당 한 번) |

배선: 앞의 세 훅은 `.claude/settings.json`, 커밋 전 검사 둘은
`scripts/git-hooks/pre-commit`.

## 잠금 상태 (`gates.json`)

`collection.state`가 `locked`이면 새 세션 수집이 차단된다. **재분석·재현·
버그 수정은 막지 않는다** — 그건 정당한 작업이고, 막으면 데이터를 고칠 수
없게 된다.

해제는 `gates.json`을 고쳐 `open`으로 바꾸는 것이지만, **유저 승인 없이
바꾸지 말 것.** 해제 조건은 파일 안에 적혀 있고, 바꾸는 커밋은 사유를
`STATUS.md` 결정 로그에도 남긴다.

## 비상 우회

가드레일은 우회 가능해야 한다. 다만 우회는 흔적이 남는다(환경 변수를 쓴
사람이 그 이유를 안다).

```bash
CASA_SKIP_STATUS_CHECK=1 git commit ...   # STATUS.md 동반 검사 건너뜀
CASA_SKIP_RECORD_CHECK=1 git commit ...   # 미기록 수집 배치 검사 건너뜀
CASA_SKIP_TASK_DESIGN=1 git commit ...    # 새 과제 설계 검문 건너뜀
CASA_ALLOW_MAIN=1 git commit ...          # main 직접 커밋 차단 해제 (기존)
```

수집 잠금에는 환경 변수 우회가 **없다.** 풀려면 `gates.json`을 고쳐야 하고,
그건 커밋에 남는다. 그게 의도다.

## 무엇을 못 막는가 (정직하게)

- "설계 지적에 측정으로 답하기"는 판단의 문제라 기계가 볼 수 없다. 수집
  잠금은 그 경로 중 **가장 비싼 하나**를 닫을 뿐이다.
- "(이 과제 집합에서 안 된다)를 (불가능하다)로 일반화하기"도 못 막는다.
  시작 앵커에 문장으로 넣어 두는 것이 현재로선 최선이다.
- 보고 규율 검사는 약어를 세는 것이지 설명이 실제로 이해 가능한지를 재지
  못한다.

이 세 가지는 유저가 직접 봐야 한다. 하네스는 사람이 볼 것의 양을 줄이는
장치이지 사람을 대체하는 장치가 아니다.
