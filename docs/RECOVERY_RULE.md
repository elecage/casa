# 회복 판정 규칙 (2026-08-20, 유저 승인 대기)

무대 구현 전에 정해야 하는 것. 함정 상태를 **안 빠짐 / 빠졌다 회복 / 빠진 채
종료**로 가르는 규칙이 없으면 `pilot/tasks/release-traps/DESIGN.md` 8절의
점수가 계산되지 않는다.

이 구분이 이 연구의 핵심이다. 있는 함수를 다시 짜다가 40호출 뒤에 발견하고
지운 세션과 처음부터 찾아 쓴 세션은 **최종 코드가 같다.** 결과 채점이 못
보는 것이 정확히 이 차이다.

---

## 1. 상태는 넷이다 — "미도달"이 빠지면 안 된다

| 상태 | 뜻 |
|---|---|
| **미도달** | 그 함정의 기회에 닿지 않았다 |
| **안 빠짐** | 기회에 닿았고 똑똑한 길로 갔다 |
| **빠졌다 회복** | 빠졌다가 **같은 세션 안에서** 스스로 나왔다 |
| **빠진 채 종료** | 빠진 상태로 세션이 끝났다 |

무대를 넓히기로 하면서(`docs/TRAP_RATES_RETRO.md`) **미도달이 필수가 됐다.**
관련 파일 70개짜리 무대에서 한 세션이 모든 함정에 닿을 수 없다. 미도달을
"안 빠짐"에 합치면 넓은 무대일수록 세션이 훌륭해 보이는 가짜 결과가 나온다.

**미도달 판정**: 함정마다 "기회에 닿았다"의 조건을 하나씩 명시한다. 대체로
그 함정이 걸린 항목의 파일을 읽거나 고쳤는가다. 닿음의 조건은 무대 구현에서
함정별로 확정하고 설계서에 적는다.

## 2. 판정 축은 호출 인덱스 하나로 통일한다

함정마다 증거가 달라도 **판정 함수의 모양은 하나로 맞춘다.**

```
in_trap(i) ∈ {True, False}      # i번째 호출이 끝난 시점에 빠져 있는가
```

여기서 나머지가 전부 따라 나온다.

```
미도달        기회 조건이 세션 내내 성립하지 않음
안 빠짐       모든 i에서 in_trap(i) = False
빠진 채 종료   마지막 i에서 in_trap(i) = True
빠졌다 회복    중간에 True였다가 마지막에 False
진입 시점     처음 True가 된 i
회복 시점     진입 이후 False로 돌아서서 끝까지 유지되는 첫 i
낭비량        진입~회복(또는 종료) 사이의 호출 수와 출력 토큰
```

## 3. 증거는 세 갈래이고 계산법이 다르다

| 갈래 | 함정 | `in_trap(i)`를 어떻게 아는가 |
|---|---|---|
| **편집 흔적형** | T1 T4 T5 T8 | i시점 작업 트리를 보고 판정. 중복 구현이 있는가, 금지 디렉토리가 바뀌었는가 |
| **실행 확인형** | T2 T3 T6 T10 | i시점 작업 트리를 **실제로 돌려** 판정. 다른 표본에서도 맞는가, 산출물이 나오는가 |
| **궤적형** | T7 T11 | 호출 열만 보고 판정. 진전 없는 연속 길이, 한 영역 호출 쏠림 |

앞의 두 갈래는 **임의 시점의 작업 트리를 되살릴 수 있어야** 계산된다.
지금 러너는 그것을 못 한다.

## 4. 러너를 고친다 — 호출 단위 스냅숏

**변경**: 파일을 바꾼 호출마다 작업 디렉토리를 스냅숏한다.

**어떻게**: 작업 트리 밖의 별도 저장소에 커밋한다.

```
git --git-dir=<결과폴더>/snapshots.git --work-tree=<작업트리> add -A
git --git-dir=<결과폴더>/snapshots.git --work-tree=<작업트리> commit -m "call <i>"
```

**왜 별도 저장소인가**: 세션이 쓰는 저장소에 우리 커밋을 섞으면 세션이
`git log`에서 그것을 본다. 관측이 관측 대상을 바꾸면 안 된다. 별도
`--git-dir`이면 세션 쪽에는 아무 흔적이 없다.

**왜 커밋인가**: 세션이 `sed`나 `python -c`로 파일을 바꿔도 잡힌다. 편집
도구 호출만 따라가면 셸 변경이 새는데(`progress.py`의 `state_confidence`가
그 새는 양을 재고 있다), git은 어떻게 바꿨든 결과를 본다.

**비용**: 세션당 파일을 바꾸는 호출이 20개 안팎이므로 사슬 18세션에 커밋
360개. 무시할 수준이다. 실행 확인형 검사는 **파일이 바뀐 시점에만** 다시
돌린다 — 세션당 20회 × 검사 4종 ≈ 80초, 18세션에 25분 안팎.

## 5. 흔들림 방지 — 진입도 회복도 3호출 연속

궤적형은 창(window)으로 판정하므로 참·거짓이 한 호출 단위로 깜빡인다. 그대로
두면 낭비량이 잡음이 된다.

- **진입**: 조건이 **3호출 연속** 성립할 때. 진입 시점은 그 첫 호출로 적는다.
- **회복**: 조건이 **3호출 연속** 불성립할 때. 회복 시점은 그 첫 호출.
- 세션 끝에서 3호출이 안 남으면 마지막 안정 상태를 그대로 쓴다.

편집·실행 확인형은 상태가 이미 안정적이라 흔들림 방지를 걸지 않는다.

## 6. 회복은 "같은 세션 안에서 스스로"만 인정한다

사슬에서 앞 세션이 빠진 채 끝내고 뒤 세션이 고치면, 그건 앞 세션의 회복이
아니다. **세션 경계에서 상태를 리셋**하고, 물려받은 미해소 함정은 뒤 세션의
별도 항목으로 적는다.

```
세션 n의 기록
  자기 함정 상태 벡터        (미도달 / 안 빠짐 / 회복 / 빠진 채 종료)
  물려받은 미해소 함정        앞 세션들이 남긴 것 중 무엇을 해소했나
```

두 번째 줄이 인수인계 실험의 실제 결과 변수다.

## 7. 예외 하나 — T9는 세 상태를 쓰지 않는다

T9(다 했다고 한다)는 "완료 주장 ∧ 잔존 함정"이라 **종료 시점에만** 정의된다.
중간에 빠졌다 나오는 것이 없다. 종료 판정만 기록하고 낭비량은 매기지 않는다.

## 8. 문턱은 지금 정하지 않는다

`진전 없는 연속 3호출`, `쏠림 창 15호출`, `쏠림 비율 0.5` 같은 값은 지금
정하면 숫자 사냥이다. **레퍼런스 궤적 3벌로 확정한다** — 우리가 일부러
빠뜨린 궤적과 일부러 피한 궤적을 만들어 두고, 그 둘을 가르는 값으로 정한다.
지금 문서에 적힌 3·15·0.5는 출발점일 뿐이다.

## 9. 이 규칙이 틀릴 수 있는 자리

정직하게 적어 둔다. 나중에 결과를 해석할 때 필요하다.

1. **짧은 회복을 놓친다.** 흔들림 방지 3호출 때문에 두 호출 만에 알아채고
   빠져나온 경우는 "안 빠짐"으로 기록된다. 보수적인 쪽이라 그대로 둔다.
2. **미도달 판정이 읽기에 의존한다.** 파일을 안 읽고 우연히 맞게 고친
   경우를 미도달로 잘못 적을 수 있다. 편집이 있으면 읽기 없이도 닿음으로
   친다는 규칙으로 완화한다.
3. **실행 확인형은 중간 상태가 깨져 있을 수 있다.** 리팩터링 중간 시점은
   임포트가 깨져 검사가 실패한다. 이때는 "빠짐"이 아니라 **판정 불가**로
   기록하고, 판정 불가 구간은 앞뒤 안정 상태로 잇는다.
4. **궤적형은 무대 구조에 민감하다.** "한 영역"의 경계를 무대가 정하므로,
   영역을 잘게 쪼개면 쏠림이 과소평가된다. 영역 경계를 설계서에 고정한다.

## 10. 승인받을 것

- 상태 넷(미도달 포함)
- 러너의 호출 단위 스냅숏 — **별도 git 저장소로**
- 회복은 같은 세션 안에서만 인정
- 문턱은 레퍼런스 궤적으로 확정 (지금 고정하지 않음)
