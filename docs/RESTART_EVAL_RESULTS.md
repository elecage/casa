## 1. 질문 (a) — 안 끊고 계속하면 정말 문제가 되는가

| | 값 |
|---|---|
| 알림이 뜬 세션 | 9 |
| **스스로 알림이 풀린 비율** | **89% (8/9)** |
| **결국 성공한 비율** | **78% (7/9)** |

알림 시점에 끊었다면 **아홉 중 일곱이 성공할 세션을 죽인 것**이 된다.

이 데이터에서 답은 명확하다. **알림 시점의 종료는 손해다.**

## 2. 질문 (b) — 끊는 정책이 나은가

성공 하나당 출력 토큰:

| 정책 | 성공당 토큰 | |
|---|---|---|
| 전부 계속 | **25,049** | 아무것도 안 함 |
| 전부 끊고 재시작 | 41,034 | 귀무 정책 — 신호를 전혀 안 씀 |
| 경보 기반 종료 | 25,078 | 오탐으로 성공 2건 사망 |

**경보 기반 정책은 아무것도 안 하는 것과 사실상 같다**(+0.1%). 귀무 정책은
확실히 이긴다(38% 우위). 즉 **신호가 해롭지는 않으나 이득도 없다.**

## 3. 왜 이득이 없는가 — 손익분기 계산

끊는 것이 이득이 되는 조건은 단순하다. 계속했을 때 낭비할 양이, 새 세션이
문맥을 다시 잡는 비용보다 커야 한다.

```
계속하면   남은 일 × m        (m = 낭비 배수)
끊으면     H + 남은 일        (H = 문맥 재확보 비용)

이득 조건   남은 일 > H / (m − 1)
```

실측:

| 항목 | 값 |
|---|---|
| **H** 문맥 재확보 비용 (첫 편집 전 소비, 중앙값) | **5,853 토큰** |
| **m** 낭비 배수 (알림 세션 / 무알림 세션 비용) | **1.29** |
| **손익분기: 남은 일이 넘어야 하는 양** | **20,528 토큰** |
| 실제 알림 이후 남은 양 | 2,419 토큰 |
| **실제 / 손익분기** | **0.12배** |

**8.5배 모자란다.** 신호를 아무리 잘 만들어도 이 과제에서는 이득이 날 수
없다. 이것은 규칙의 실패가 아니라 **과제 크기의 문제**이고, 사전 예측 3번이
그대로 맞았다.

### 가장 중요한 숫자: H가 세션의 72%다

문맥 재확보 비용 5,853은 세션 총 비용 중앙값 8,074의 **72%**다. 이 과제들은
비용의 대부분이 "읽고 파악하기"에 있고 **끊으면 그걸 통째로 다시 내야 한다.**
재시작이 비싼 진짜 이유가 이것이다.

## 4. 그래서 최소 프로젝트 크기는 얼마인가

알림이 세션의 φ 지점에 뜬다고 하면 남은 일은 `(1−φ) × 총량`이므로:

```
총량 > H / ((m − 1) × (1 − φ))
```

| 알림 시점 φ | 필요한 세션 총량 | 현재(8,074)의 몇 배 |
|---|---|---|
| 0.78 (현재 실측) | **92,000 토큰** | 11배 |
| 0.50 | 41,000 토큰 | 5배 |
| 0.30 | 29,000 토큰 | 3.6배 |
| 0.20 | 26,000 토큰 | 3.2배 |

**두 개의 손잡이가 있고 둘 다 필요하다.** 세션을 키우는 것과 알림을 앞당기는
것. 알림을 78%에서 30% 지점으로 당기면 필요한 크기가 3분의 1로 준다.

그리고 **H를 줄이는 세 번째 손잡이**가 있다 — 인수인계다. 5절.

## 5. 한계 — 이 계산이 가정하는 것

1. **단발 과제와 연속 프로젝트는 경제가 다르다.** 위 식은 "끊어도 저장소
   상태는 남는다"를 가정한다(연속 프로젝트). 지금 실험은 단발이라 끊으면
   **작업 전체가 사라지므로** 실제로는 더 나쁘다. 즉 위 손익분기는 **낙관적
   상한**이다.
2. **m = 1.29는 알림 표본 9개에서 나왔다.** 신뢰구간이 넓다.
3. **프롬프트를 고쳐 재시작하는 경우는 여전히 미검정.**
4. 사람이 알림을 보고 판단하는 지연을 0으로 가정했다.

## 6. 결론

- 이 과제군에서 **끊기는 이득이 아니다.** 규칙 때문이 아니라 과제가 짧아서다.
- 방향을 바꿀 것은 신호가 아니라 **실험 대상의 크기와 형태**다.
- 필요한 최소 크기가 숫자로 나왔다: 알림이 30% 지점에 뜬다는 조건에서
  **세션당 약 29,000 출력 토큰**, 현재의 3.6배.
