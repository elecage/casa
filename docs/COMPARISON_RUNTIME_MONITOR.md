# 비교 논문 정밀 분석 — 실시간 무라벨 병리 탐지 (arXiv 2608.02464)

**Real-Time Detection and Repair of LLM Agent Failures**
https://arxiv.org/html/2608.02464v1 (2026-08 프리프린트, 본문 확인 2026-08-19)

이 논문은 **현재 우리 방향의 최근접 선행 연구**다. "정답 라벨 없이, 모델
내부 없이, 진행 중에 병리를 탐지한다"는 조합을 이미 실증했다. 따라서 그
조합 자체는 우리 노벨티가 될 수 없다. 이 문서는 (1) 논문을 정확히 정리하고
(2) 갭을 특정하고 (3) 우리가 무엇을 하는지를 고정한다.

투고 전 개정판·심사 상태를 반드시 재확인할 것.

---

## 1. 논문이 하는 일

에이전트가 도는 동안 텔레메트리를 감시해 경보를 울리고, 경보가 뜬 실행을
마지막 사실 수집 지점으로 되감아 다시 실행한다.

**탐지기 구조**: 정상 에피소드만으로 "다음 스텝이 무엇일지"를 예측하도록
맞춘 뒤, 예측이 빗나가는 정도를 매 스텝 누적한다. 누적치가 문턱을 넘으면
경보. 실패 사례를 하나도 쓰지 않는다(단일 클래스 이상 탐지).

- 저수지 연산(echo-state network) 앙상블 — 순환 가중치는 **학습하지 않고**
  고정 난수, 읽기 층만 능형 회귀로 정상 데이터에 맞춘다. 학습 1.7초
  (비교: GRU 68초).
- 채널별로 누적합(CUSUM) 변화 탐지, 채널 최댓값으로 경보.
- 문턱은 정상 검증 세션의 (1−β) 분위수. 시험 데이터에서 뽑지 않는다.

**입력 채널 (총 43~60차원)**:

| 채널 | 내용 | 차원 |
|---|---|---|
| 의미 임베딩 | 출력의 문자 3-그램 해시. **신경망·네트워크 불요** | 32 |
| 토큰 불확실도 | 토큰 단위 확신도 집계 (모델 로그확률 필요) | 4 |
| 행동 메타데이터 | 행동 원-핫, 로그 지연, 출력 길이, 에러 플래그 | 7+ |
| (확장) 파생 행동 | 코사인 드리프트, 과제 기준점 유사도, 도구 성공, 재시도 수, 문맥 비율, 깊이, 자기 일관성 | 8 |
| (확장) 내용 접지 | 질의-결과 비유사도, 결과 자기 일관성, JSON 접두 유효성, 문자 이상, 어휘 관련 플래그 | 9 |

**규모**: 프레임워크 3종(자체·LangGraph·AutoGen), 데이터셋 25종, 에피소드
2,823개, 모델 4종(qwen2.5 7b/3b, llama3.1 8b, gemini-2.5-flash).
스텝당 감시 ~200μs, 텔레메트리 어댑터 중앙값 674μs — 합쳐 1ms 미만.

**평가 대상 실패**: 기계적으로 검증 가능한 4종을 **주입**(루프, 도구 연쇄
실패, 목표 이탈, 내용 오염)해 발생 시점의 정답을 만든다. 자연 발생분은
고온 30에피소드에서 11건(조용한 중단 7, 수치 날조 3, 근거 없는 검색 혼합 1).

**비교 기준선 11종**: 무기억 마할라노비스, 고립 숲, 선형 자기회귀,
GRU/LSTM/TCN 등.

## 2. 성적

| 실패 종류 | 탐지율 |
|---|---|
| 루프 | 0.48 ~ 1.00 |
| 도구 연쇄 실패 | 0.17 ~ 1.00 (9개 중 7개 데이터셋에서 0.55+) |
| 목표 이탈 (급격한 경우) | 0.66 ~ 0.86 |
| 내용 오염 — 엉뚱한 문서 | 0.00 ~ 0.20 |
| 내용 오염 — 형식 깨짐 | 0.05 ~ 0.50 → 내용 접지 채널 추가 시 0.90 |

- 탐지 선행 시간 약 4.6스텝. 관측 지평이 길수록 유리(지평 ≤3스텝에서는
  무기억 기준선 대비 +0.09, 4~8에서 +0.14, ≥9에서 +0.40).
- **결정론적 검증 검사와의 대조 (이 논문의 가장 중요한 표)**:

  | 방식 | 잡은 비율 | 헛경보 |
  |---|---|---|
  | 결정론적 검증 검사 | 60% (커버리지 검사 포함 96%) | **0/63** |
  | 통계 감시기 | 54% | **17%** |

- 산출물 유무 확인만으로 조용한 중단 7/7을 다 잡았다(헛경보 0).

**수리(repair)**: 경보 난 실행을 되감아 다시 굴린다. 과제 성공률 52% →
73%, 실패 25건 회복, 정상 실행을 깨뜨린 사례 0.

| 개입 방식 | 회복률 | 유의성 |
|---|---|---|
| 무개입 | 0% | — |
| 그냥 다시 굴리기 (대조군) | 16% | 기준 |
| **실패한 검사의 이름만 알려주기** | **45%** | p=0.0005 |
| 일반적 재확인 요구 | 36% | p=0.0347 |
| 구체적 값 제공 | 36% | p=0.0192 |
| 계산기로 재계산 | 28% | 유의하지 않음 |

## 3. 논문이 스스로 인정한 한계

1. **배포가 바뀌면 무너진다.** 한 모델로 보정 후 다른 모델에 적용 시
   AUROC 0.527(동전 던지기), 대상에서 재보정하면 0.885. 저자 표현:
   "실패한 것은 보정이지 어려운 대상이 아니다."
2. **온도 설정만 바꿔도 정상 세션의 36%에 헛경보.** 정상 분포가 설정에
   극도로 민감하다.
3. **느린 목표 이탈은 시험한 모든 매 스텝 감시기를 빠져나간다.** 궤적 자기
   일관성만이, 그것도 약하게 본다.
4. **그럴듯한 값의 오염은 원리적으로 탐지 불가**하며 외부 기준이 필요하다고
   명시.
5. **날조 연구는 표본 부족을 스스로 선언.** 사전 등록 55에피소드에서 필요
   최소 10건 대비 2건만 관측, 탐지 주장을 하지 않음.
6. **외부 벤치마크 전이 실패.** 헛경보 5% 예산에서 탐지율 0.048.

## 4. 이 논문이 우리에게 준 것 (인용할 근거 셋)

**(1) 모델 내부는 필요 없다는 실증.** 토큰 불확실도 채널을 제거한 절제
실험에서 판별력 변화가 **정확히 +0.000**, 탐지율 +0.002. 저자 결론:
구조화된 도구 결과가 로그확률 접근보다 중요하다.

→ 폐쇄 상용 도구를 다루느라 로그확률에 접근할 수 없다는 우리 제약이
**성능상 손해가 아님**을 경쟁 논문이 증명했다.

**(2) 결정론적 검사가 통계 감시기보다 낫다는 실증.** 위 표(60%/헛경보 0
대 54%/헛경보 17%). 우리 설계 원칙("감사 엔진은 결정론을 유지, LLM 심판은
보조")을 외부 데이터가 지지한다.

**(3) 정보의 구체성이 회복률을 세 배로 만든다.** 실패한 검사의 **이름만**
알려주는 것이 45%, 그냥 다시 굴리기가 16%. 값까지 주는 것(36%)보다도 나았다.

→ 우리는 개입 방식을 가져올 수 없지만(5절) 이 교훈은 **알림 문구 설계**로
옮긴다. "이 세션 이상함"이 아니라 "같은 명령 12회 반복, 파일 변화 없음".

## 5. 우리 설정과의 구조적 차이 — 외부 앱

**결정 (2026-08-19, 유저)**: 탐지기는 **외부 앱**으로 만든다. 클로드 코드
프로세스 밖에서 트랜스크립트를 따라 읽으며 관찰한다.

**실현 가능성 확인 (2026-08-19)**: 진행 중 세션의 트랜스크립트 JSONL이
**메시지마다 실시간으로 덧붙여진다.** 확인 방법 — 진행 중이던 세션 파일의
마지막 줄 타임스탬프가 확인 시각보다 4초 전이었다(기록 09:39:54Z, 확인
09:39:58Z, 634줄). 훅도 설정 변경도 프로젝트 결합도 없이 초 단위 지연으로
관찰 가능하다.

| | 외부 앱 | 이 논문의 감시기 |
|---|---|---|
| 위치 | 실행 루프 **밖** | 루프 **안** |
| 관찰 | 트랜스크립트 파일 따라 읽기 | 자체 텔레메트리 스트림 |
| 도구 호출 차단 | 불가 (프로젝트 훅이어야 함) | 가능 |
| 세션에 말 끼워넣기 | **불가** | 가능 |
| 되감아 재실행 | **불가** (기능 자체가 없음) | 가능 |
| 세션 종료 | 가능 (프로세스 종료) | 가능 |
| 사람에게 알림 | 가능 (본래 역할) | 해당 없음 |

**따라서 "끼어들어 지적하기"는 우리 지렛대 목록에서 제외한다.** 논문이 그걸
할 수 있었던 것은 자기가 만든 시스템을 감시했기 때문이다. 남는 지렛대는
**알린다**와 **끊는다** 둘뿐이며, 이는 유저의 원래 목표("초반에 판별해
끊고 재시작")와 일치한다.

이 제약이 연구에 주는 이점 셋:

- **오탐 비용이 싸진다.** 자동 종료 설계에서는 헛경보 하나가 잘 가던 세션을
  죽인다. 알림 설계에서는 헛경보의 비용이 사람의 주의 한 번이다. 따라서
  **문턱이 둘로 갈린다** — 알림 문턱(낮게)과 종료 권고 문턱(높게). 지금까지
  우리는 문턱을 하나만 계산했다.
- **주장 범위가 깨끗해진다.** "탐지 + 재시작 정책"을 묶어 평가하던 구조에서는
  재시작이 손해면 탐지도 같이 무의미해졌다. 알림 설계에서 우리가 책임지는
  것은 "제때 맞는 것을 알렸는가" 하나다.
- **새 갭이 생긴다.** 루프 밖에서 관찰만 하고 사람에게 알리는 설정은 이
  논문이 다루지 않았다. 폐쇄 상용 도구 사용자에게는 그것이 유일하게 가능한
  형태다.

## 6. 갭 목록과 우리가 할 것

### 갭 1 — 정상 기준선이 예고 없이 움직이는 환경 (최대 갭)

이 방법의 전제는 "이 배포의 정상 세션"을 모아 기준선을 맞추는 것이다.
온도 하나만 바뀌어도 헛경보 36%, 모델이 바뀌면 판별력 0.527.

그런데 폐쇄 상용 도구 사용자에게 배포 변경은 **통보 없이** 일어난다.
**우리에게 실측 증거가 있다**: 같은 과제·같은 기록상 모델 식별자로 돌린
배치의 성공률이 33%에서 87%로 바뀌었다(파일럿 §3). 기록된 버전으로는
설명되지 않았다.

→ **우리가 할 것**: 기준선 학습이 필요 없는 지표. 세션을 모집단이 아니라
**그 세션 자신의 앞부분과 비교**한다. "같은 호출이 38번 반복됐다"는 다른
세션을 하나도 안 보고 판정된다. 배포가 바뀌어도 헛경보율이 흔들리지 않는다.

### 갭 2 — 새 사용자에게는 기준선이 없다 (콜드 스타트)

수백 개의 정상 세션이 있어야 쓸 수 있다. 외부 벤치마크 전이 시 탐지율
0.048이 이를 보여준다. 처음 설치한 사용자는 비교할 정상 세션이 0개다.

→ **우리가 할 것**: 첫 세션부터 작동하는 규칙 기반 지표를 우선순위 위로.

### 갭 3 — 심은 고장 대 자연 발생 실패

4종을 주입해 발생 시점 정답을 만들었다. 자연 발생 표본은 11건, 날조 축은
표본 부족으로 주장을 포기했다. **심을 수 있는 고장만 다룬다**는 것은 심을
수 없는 실패는 다루지 못한다는 뜻이다.

→ **우리가 가진 것**: 실제 과제에서 자연 발생한 127세션. 지배 현상이 허위
완료였다(한 조건에서 실패 55건 중 53건이 완료 주장, 그것도 검증 실행 후).
이 논문이 표본 부족으로 포기한 축이다.

### 갭 4 — 이상함과 나쁨을 같은 것으로 본다

이 방법은 "정상 분포에서 벗어남"을 잡는다. 그러나 우리 문제에는 **정상처럼
보이는데 낭비인 세션**이 있다 — 같은 조건에서 최종 출력 토큰 27~60,527인데
둘 다 성공했다면 이 감시기에게는 둘 다 정상이다. 반대로 꼼꼼해서 오래 걸린
세션은 헛경보로 잡힌다.

→ **우리가 할 것**: 이상 탐지가 아니라 **낭비 탐지**. 기준이 "전형에서
벗어났나"가 아니라 "진전 없이 소비했나"다. 성공한 세션도 낭비였다고 말할
수 있어야 한다.

### 갭 5 — 느린 지시 이탈을 못 잡는다 (저자가 명시)

"시험한 모든 매 스텝 감시기를 빠져나간다." 이유는 지시 이탈이 **놀라움으로
나타나지 않기** 때문이다 — 규칙을 어기는 행동도 그 자체로는 전형적이다.

→ **우리가 가진 것**: 규칙 위반을 도구 호출 단계에서 결정론적으로 대조하는
엔진(`rules/`, `src/casa/rules.py`)이 이미 있다. 놀라움이 아니라 대조로
판정하므로 이 한계에 걸리지 않는다. 실물 사례도 있다 — 한 세션이 규칙 위반
58건인데 같은 조건의 다른 6세션은 0건이었다.

### 갭 6 — 개입 비용을 계산하지 않는다

되감아 재실행하는 방식은 자체 시스템이라 가능하다. 또 헛경보율 17%를
보고하면서 **그것이 얼마를 낭비시키는지**는 계산하지 않는다.

→ **우리가 할 것**: 사용자가 실제로 쓸 수 있는 지렛대(알림·종료)만으로 된
결정 규칙, 그리고 오탐 비용을 명시적으로 넣은 계산. 알림 문턱과 종료 문턱을
따로 잡는다.

### 갭 7 — 얼마나 아꼈는지를 재지 않는다

탐지 시점을 "고장 발생보다 4.6스텝 앞섰다"로 보고한다. 그것이 토큰으로
얼마인지는 없다. 사용자의 질문은 스텝이 아니라 비용이다.

→ **우리가 할 것**: 절감량을 스텝이 아니라 출력 토큰으로 보고.

## 7. 우리 위치 (한 문단)

이 논문의 방법이 성립하려면 "이 배포의 정상 세션"이라는 안정된 기준선이
필요한데, **폐쇄 상용 도구 사용자에게는 그 기준선이 예고 없이 움직이고, 새
사용자에게는 아예 없다.** 우리는 기준선 학습이 필요 없는 결정론적 지표로
같은 일을 하되, 감시기를 실행 루프 밖의 외부 앱으로 두어 알림과 종료만을
지렛대로 쓴다. 그리고 이 논문이 표본 부족으로 포기한 허위 완료 축과, 못
잡는다고 명시한 느린 지시 이탈 축을, 주입이 아닌 자연 발생 데이터로 채운다.
