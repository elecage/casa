# 경보 규칙 — 사전 등록 설계 (2026-08-19)

**이 문서는 데이터를 보기 전에 쓴다.** 지표를 다 만들어놓고 결과를 보면서
조합과 문턱을 정하면 그것은 발견이 아니라 사후 조작이다. 그래서 규칙·문턱·
예측을 먼저 고정하고, 그다음 기존 127세션에 돌린다.

문턱을 바꾸려면 **왜 바꾸는지와 언제 바꿨는지를 `STATUS.md` 결정 로그에
남긴다.** 조용히 고치지 않는다.

---

## 1. 설계 제약 (앞선 결정에서 따라오는 것)

| 제약 | 출처 |
|---|---|
| 앞에서부터 순서대로만 계산. 뒤를 미리 못 봄 | 외부 앱 (`docs/ARCHITECTURE.md`) |
| 다른 세션 기준선 없이 작동 | 콜드 스타트·기준선 이동 (`docs/COMPARISON_RUNTIME_MONITOR.md` 갭 1·2) |
| 결정론적. 학습·심판 없음 | `CLAUDE.md` 설계 원칙 |
| **문턱이 둘** — 알림용(낮게)·종료 권고용(높게) | 외부 앱은 헛경보 비용이 "주의 한 번" |
| 알림에 **무엇이 걸렸는지**가 들어가야 함 | 구체성이 회복률을 세 배로 만듦(45% 대 16%) |

## 2. 왜 점수 합산이 아니라 이름 붙은 규칙인가

두 가지 방식이 가능하다.

- **점수 합산**: 신호들에 가중치를 주어 한 숫자로 만들고 문턱을 넘으면 경보.
- **규칙 발화**: 병리마다 독립 규칙을 두고, 어느 하나라도 조건을 만족하면
  그 규칙 이름과 함께 경보.

**규칙 발화를 택한다.** 이유 셋:

1. **가중치는 맞춰야 하고, 맞추려면 데이터를 봐야 한다.** 그 순간 사후
   조작이 된다. 규칙 발화는 맞출 가중치가 없다.
2. **점수는 사람에게 할 말이 없다.** "0.73"은 판단 근거가 못 된다. 외부 앱의
   지렛대는 알림뿐이므로 이건 치명적이다.
3. **병리가 질적으로 다르다.** 헛도는 것과 증거가 멈춘 것과 에러를 무시하는
   것은 다른 상태이고, 대응도 다르다. 하나로 뭉개면 정보가 사라진다.

## 3. 문턱을 어디서 가져오는가

**우리 데이터로 맞추지 않는다. 외부 연구의 실측에서 가져온다.** 그래야
"맞춰놓고 잘 맞는다"가 되지 않는다.

| 근거 | 값 | 출처 |
|---|---|---|
| 성공한 회복에 걸린 스텝 (중앙값) | **5** | `Failure as a Process` (arXiv 2607.09510) |
| 실패한 회복에 걸린 스텝 (중앙값) | **12** | 같은 논문 |
| 되돌릴 수 없게 된 뒤 남은 스텝 (유형별 중앙값) | 8~21 | 같은 논문 |
| 반복 행동의 통상 정의 | 동일 호출 **연속 3회** | 실무 도구들의 공통 정의 |
| 행동 순환의 통상 정의 | 길이 3 이상 묶음이 **2회 이상** | 같은 곳 |

해석: **진전 없이 5스텝이면 성공적 회복의 통상 길이를 이미 다 썼다**(알림
근거). **12스텝이면 실패한 회복의 통상 길이에 도달했다**(종료 권고 근거).

## 4. 규칙 목록 (사전 등록)

전부 세션 자기 자신만 보고 판정한다. `진전`은 `docs/PROGRESS_RULE.md`의
세 갈래(앎·산출·증거)를 뜻한다.

| ID | 이름 | 발화 조건 | 알림 | 종료 권고 |
|---|---|---|---|---|
| **R1** | 완전 정지 | 앎·산출·증거가 **모두 0**인 호출이 연속 K회 | K=5 | K=12 |
| **R2** | 동일 호출 반복 | 완전히 같은 (도구, 인자)가 연속 K회 | K=3 | K=6 |
| **R3** | 행동 순환 | 길이 3 이상 행동 묶음이 K회 반복 | K=2 | K=3 |
| **R4** | 증거 정지 | 산출 +가 있었고, 그 뒤 확인 호출 m회가 **전부 증거 0** | m=3 | m=6 |
| **R5** | 에러 무반응 | 에러 직후 호출이 직전과 동일(정규화)한 경우가 연속 K회 | K=3 | K=5 |
| **R6** | 되돌림 반복 | 산출 −1의 누적이 K회 | K=3 | K=5 |
| **R7** | 조사 마비 | 앎은 계속 +인데 **산출이 한 번도 없이** 호출 N회 경과 | N=30 | **없음** |

### 규칙별 주의

- **R4는 확인 호출이 실제로 있어야 발화한다.** 확인을 아예 안 하는 세션은
  증거가 영원히 0인데, 그건 "증거 정지"가 아니라 다른 병리(검증 부재)다.
  최소 m회의 확인 호출을 요구해 둘을 갈라놓는다.
- **R7에는 종료 권고를 두지 않는다.** 긴 조사가 정당한 과제가 실제로 있고,
  그것을 죽이는 비용이 크다. 알림까지만 한다.
- **R2·R3는 진전 규칙이 없어도 계산된다.** 진전 구현이 늦어도 이 둘은 먼저
  검증할 수 있다.

### 억제 규칙

- 세션의 **첫 3호출 동안은 어떤 규칙도 발화하지 않는다.** 시작 직후에는
  판단 근거가 부족하다.
- 문맥 압축 직후 3호출도 억제한다. 압축으로 `앎` 기억이 초기화되므로
  경계에서 판정이 불안정하다.

## 5. 두 문턱의 합성

**알림**: 어느 규칙이든 알림 조건을 만족하면 발화한다. 알림 문구에 **규칙
이름과 실제 수치**를 넣는다.

```
R1 → "12번째 호출째 새로 읽은 것도, 바뀐 파일도, 달라진 확인 결과도 없습니다"
R2 → "같은 명령을 연속 4번 실행했습니다"
R4 → "5번 고쳤는데 확인 결과가 3번 연속 그대로입니다"
R5 → "에러가 난 뒤 같은 명령을 3번 반복했습니다"
```

**종료 권고**: 다음 중 하나.

- (a) 어느 규칙이든 **종료 문턱**을 넘음, 또는
- (b) **서로 다른 규칙 2개가 동시에 알림 상태**

(b)는 가중치 없는 투표다. 맞출 것이 없으므로 사후 조작 여지가 없다.

## 6. 경보의 해제와 기록

| | 동작 |
|---|---|
| **앱 동작** | 규칙의 조건이 더 이상 성립하지 않으면 그 규칙의 알림은 해제된다. 모든 규칙이 해제되면 세션 알림도 내린다 |
| **분석 기록** | 규칙별 **최초 발화 호출 번호**를 고정 기록한다. 해제 여부와 무관하다 |

해제를 허용하는 이유: 해제되지 않는 알림은 소음이 되고, 사람이 무시하기
시작하면 장치 전체가 무의미해진다.

분석에서 최초 발화를 고정하는 이유: `docs/RESTART_EVALUATION.md`의 τ가
바로 이 값이다. 그 시점에 끊었다면 무엇을 아꼈을지를 계산해야 한다.

**추가로 얻는 값**: 알림이 해제된 비율(= 세션이 스스로 빠져나온 비율).
이것이 높으면 종료 권고는 더 보수적이어야 한다는 뜻이다.

## 7. 무엇으로 평가하는가 (순환 논증 차단)

경보의 입력은 행동이다. 그러니 **평가는 행동이 아닌 것으로만** 한다.
`docs/RESTART_EVALUATION.md` 0절과 같은 규칙이다.

| | 경보 입력 | 평가 지표 |
|---|---|---|
| 진전 세 갈래, R1~R7의 계수 | **입력** | 쓰지 않음 |
| 최종 달성 (숨은 오라클) | 아님 | **사용** |
| 총 소비 출력 토큰 | 아님 | **사용** |
| 허위 완료 여부 | 아님 | **사용** |
| 세션 총 소요 호출 수 | 아님 | 사용 |

## 8. 사전 예측 (데이터를 보기 전에 적는다)

맞든 틀리든 이 예측을 나중에 고치지 않는다.

1. **알림은 발화하고 종료 권고는 거의 발화하지 않을 것이다.** 지금 과제의
   도구 호출 중앙값이 13~19회라 R1의 종료 문턱(연속 12회 정지)에 도달할
   여지가 거의 없다.
2. **퇴화 세션 1건은 잡힐 것이다** — `results/main2/ml-shift-sonnet`의 도구
   호출 248회·동일 호출 38회 세션. R2가 가장 먼저 발화할 것으로 본다.
3. **따라서 이 데이터에서 절감 효과는 작게 나올 것이다.** 그것은 규칙의
   실패가 아니라 **과제가 짧다는 사실의 반영**이다. 두 가지를 섞어 읽지
   말 것 — 여기서 효과가 없다고 "탐지가 불가능하다"로 일반화하는 것이
   이 프로젝트가 이미 세 번 저지른 오류다.
4. **R5(에러 무반응)가 R1보다 일찍 발화할 것이다.** 외부 실증에서 에러
   대응률 차이가 가장 컸다(성공 92% 대 실패 37%).

## 9. 이 설계가 실패했다고 판정하는 기준

미리 적어둔다. 사후에 기준을 바꾸지 않기 위해서다.

- **헛경보**: 같은 조건에서 정상적으로 성공한 세션에 알림이 20% 넘게
  뜨면 알림 문턱이 너무 낮다.
- **놓침**: 퇴화 세션(248호출)이 **끝까지 한 번도 발화하지 않으면** 규칙
  집합이 잘못된 것이다.
- **무용**: 종료 권고가 한 번도 발화하지 않고, 알림도 세션 종료 직전(마지막
  20% 구간)에만 뜬다면 실용 가치가 없다.

**실패 시 대응**: 문턱을 조용히 낮추지 않는다. 한 조건에서 조정하고 다른
조건에서 검증하며, 조정 사실과 이유를 결정 로그에 남긴다.
