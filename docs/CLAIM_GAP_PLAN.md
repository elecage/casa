# 완료 보고 판별 — 사전 등록 (2026-08-20)

**데이터를 보기 전에 쓴다.** 신호를 여럿 갖고 있으므로, 결과를 본 뒤 잘 나온
것을 고르면 그건 발견이 아니라 낚시다.

기존 220세션만 쓴다. **새 수집 없음, 수집 잠금 유지.**

---

## 0. 이 작업이 원래 목표에서 어디쯤인가

기록된 질문은 둘이고 이건 그중 하나다.

| 질문 | 상태 |
|---|---|
| ① 세션마다 능력이 다른가, 초반에 판별해 끊을 수 있는가 | **미검정 — 열려 있음** |
| ② 완료 보고를 믿어도 되는가 | 이 문서 |

**②를 한다고 ①이 닫히는 것이 아니다.** 아래 4절에 ①로 돌아가는 조건을
미리 적어 둔다. 이 프로젝트는 한 축을 붙들다 다른 축을 잃은 전례가 있다.

## 1. 묻는 것

> 세션이 "다 했다"고 할 때, **그 보고를 믿어도 되는지**를 세션의 행동 기록
> 만으로 판별할 수 있는가.

실용 형태: 외부 앱이 세션 종료 시 **"다 했다고 하는데 근거가 없습니다"**를
띄운다. 중간에 끊으라고 권하는 것이 아니라 **끝에 믿지 말라고 알리는 것**
이다 — 경보가 어차피 세션의 78% 지점에서야 뜨고 끊는 것은 손해라는 실측
(`docs/RESTART_EVAL_RESULTS.md`)과 맞는 형태다.

## 2. 쓸 신호 (전부 구현돼 있음)

| 신호 | 어디 |
|---|---|
| 완료 주장 여부 | `casa.metrics.claims_completion` |
| 검증 없는 완료 주장 | `casa.metrics.unverified_completion_claim` |
| 마지막 편집 후 검증 | `verification_signals.verified_end` |
| 단언 어휘 밀도 | `casa.signals.assertion_density` |
| 읽기 편중 | `casa.signals.read_heavy_tail` |
| 가짜 구현 편집 | `casa.signals.stub_edit_count` |
| 정직한 실패 표현 (역방향) | `casa.signals.honest_failure_language` |
| 헛된 확인 | `casa.signals.futile_check_count` |

**주 지표**는 외부 실증이 있는 둘 — 단언 어휘 밀도(0.825 보고)와 읽기
편중(0.953 보고). 나머지는 탐색 지표다. 탐색에서 나온 것은 발견이 아니라
후보다.

## 3. 평가 방법

- 대상: **완료를 주장한 세션**만. 주장하지 않은 세션은 애초에 믿을지 말지의
  문제가 아니다.
- 정답: 채점기의 성공/실패. **신호의 입력이 아니므로 순환이 아니다.**
- 판별력은 AUROC로 본다(무작위로 고른 허위 완료 세션이 정직한 세션보다 그
  값이 높을 확률, 0.5면 동전 던지기).
- **과적합 방지**: 문턱을 한 조건에서 정하고 **다른 조건에서 평가**한다.
  조건이 여럿 있다(궤도 60 / 원장 30 / 일정 30 / ml-shift 7 / 파일럿 4종).
- **전부 계산하고 전부 보고한다.** 잘 나온 것만 고르지 않는다.

## 4. 사전 예측 (나중에 고치지 않는다)

1. **완료 주장률이 매우 높을 것이다** — 파일럿에서 실패 13세션 중 12건이
   완료를 단언했다. 따라서 "주장했는가"는 그 자체로 신호가 아니다.
2. **"주장 전에 검증했는가"가 가장 강할 것이다** — 파일럿에서 이미 강신호로
   관찰됐다.
3. **단언 어휘 밀도는 외부 보고(0.825)보다 약할 것이다** — 그 연구는 대화형
   과제이고 우리는 코딩 과제다.
4. **읽기 편중은 우리 데이터에서 약할 것이다** — 그 연구는 API 호출 기반이고
   우리 과제는 파일 편집 중심이다.

## 5. 실패 판정 기준

- **표본 부족**: 완료를 주장한 세션이 전체의 50%에 못 미치면 이 축을 이
  데이터로 다룰 수 없다.
- **판별 실패**: 최고 신호의 판별력이 0.65 미만이면 실용 가치가 없다.
- **일반화 실패**: 한 조건에서 정한 문턱이 다른 조건에서 0.55 아래로
  무너지면 조건을 넘지 못하는 것이다.

실패해도 **신호를 바꿔가며 다시 돌리지 않는다.** 실패는 실패로 기록하고
6절로 간다.

## 6. ①로 돌아가는 조건 (미리 적어 둔다)

아래 중 **어느 하나라도** 해당하면 이 축을 접고 질문 ①(세션 간 능력 차이)로
돌아간다.

1. 5절의 실패 기준 중 하나라도 걸렸을 때.
2. 판별이 성공했고 외부 앱에 넣을 규칙까지 확정했을 때 — **성공해도 돌아
   간다.** 이 축은 두 질문 중 하나일 뿐이다.
3. 이 축에서 세 번 연속 새 분석을 돌리는데 새 결론이 안 나올 때.

②가 잘 되든 안 되든 ①은 여전히 미검정이다. 그 사실을 `harness/anchor.md`에
박아 두었으므로 다음 세션도 같은 상태를 본다.
