# 끊기 대 계속 — 검증 설계 (2026-08-19)

유저 질문(2026-08-19): **"끊어야 하는 세션이 나왔을 때 안 끊고 계속하면
정말 문제가 생기는가? 그리고 끊고 새 세션에서 한 것과 비교할 수 있는가?"**

이것이 이 연구의 가치 주장 전체가 걸린 질문이다. 탐지기가 아무리 잘
맞혀도 (a) 계속해도 별일 없거나 (b) 새로 시작한 게 더 나쁘면 쓸모가 없다.

---

## 0. 먼저 피해야 할 순환 논증

병리를 **행동으로** 정의했으므로, 경보를 다시 행동으로 평가하면 동어반복이
된다. "헛돌았다고 판정한 세션이 헛돌았다"는 발견이 아니다.

**따라서 평가 지표는 경보의 입력이 아닌 것으로만 쓴다.**

| | 경보의 입력 | 평가 지표 |
|---|---|---|
| 진전 세 갈래 (앎·산출·증거) | **입력** | 쓰지 않음 |
| 최종 달성 (숨은 오라클 채점) | 입력 아님 | **평가에 사용** |
| 총 소비 출력 토큰 | 입력 아님 | **평가에 사용** |
| 허위 완료 여부 | 입력 아님 | **평가에 사용** |

이 프로젝트는 전에 "재는 대상을 그 측정 방식으로 정의"하는 오류를 범한
적이 있다(`docs/W15_ABILITY_EARLY.md`). 반복하지 않기 위해 위 분리를
설계에 고정한다.

---

## 1. 질문 (a) — 안 끊으면 정말 문제가 생기는가

**이건 이미 모은 데이터로 완전히 답할 수 있다.** 우리 127세션은 전부
**끊지 않고 끝까지 간** 기록이다. 즉 "계속했을 때 무슨 일이 일어나는가"는
관측이 끝나 있다. 새 수집이 필요 없다(수집 잠금 유지).

계산할 것:

| 값 | 정의 | 왜 필요한가 |
|---|---|---|
| 경보 시점 τ | 진전 규칙이 처음 경보를 낸 호출 번호 | 얼마나 일찍 아는가 |
| 경보까지 소비 C(τ) | τ까지 태운 출력 토큰 | 이미 잃은 것 (매몰) |
| 경보 이후 소비 R | τ 이후 끝까지 태운 출력 토큰 | **끊었다면 아꼈을 양** |
| **회복률** | 경보가 뜬 세션 중 결국 성공한 비율 | **이게 높으면 끊는 것이 파괴적이다** |
| 대조군 | 경보가 안 뜬 세션의 성공률·총 소비 | 경보가 무의미한 세션을 고르는 건 아닌지 |

**회복률이 이 질문의 답이다.** 경보 뒤에도 절반이 회복한다면 "계속하면
문제가 생긴다"는 주장은 성립하지 않는다.

비교 논문의 관련 실측: 회복 자체는 일어나지만, 성공한 회복은 중앙값
5스텝, 실패한 회복은 12스텝이 걸렸다. 그리고 되돌릴 수 없게 된 지점 이후의
행동은 대부분 낭비였다(`docs/COMPARISON_RUNTIME_MONITOR.md`).

## 2. 질문 (b) — 끊고 새로 한 것과 비교할 수 있는가

**할 수 있다. 다만 근사다.** 같은 세션의 두 갈래를 동시에 관측할 수는
없으므로(하나를 끊으면 계속한 결과가 없다), 재시작 쪽은 **같은 배치의 다른
세션**으로 대신한다.

**이 대체를 정당화하는 것이 이미 한 세션 독립성 검정이다.** 구조적 격리
(세션마다 template 새 복사·별개 git·별개 트랜스크립트 디렉토리)와 행동
검정(성공률에 수렴 추세 없음, 인접 세션 궤적 유사도 0.386 대 먼 쌍
0.371)으로 세션들이 서로 영향을 주지 않음을 확인했다
(`pilot/analysis/session_independence.py`). 서로 독립이므로 배치의 다른
세션은 "새로 시작했을 때"의 정당한 표본이다.

### 비교식

경보가 뜬 세션 하나에 대해:

```
계속했을 때   총비용 = C(τ) + R          결과 = 그 세션의 실제 성공 여부
끊었을 때     총비용 = C(τ) + E[C_full]  결과 = 배치의 기본 성공률
```

`C_full`은 같은 배치에서 무작위로 뽑은 세션 하나의 총 소비다. C(τ)는 어느
쪽이든 이미 쓴 돈이므로 양쪽에 다 들어간다.

### 정책 비교 — 반드시 귀무 정책을 함께 계산한다

성공 하나당 토큰으로 비교하되, **신호를 안 쓰는 정책 둘을 같이 계산한다.**

| 정책 | 내용 |
|---|---|
| 전부 계속 | 아무것도 안 함 |
| **전부 끊기** | 신호 무시하고 모든 세션을 스텝 k에서 끊고 다시 시작 |
| 경보 기반 끊기 | 우리 규칙 |

**"전부 끊기"를 반드시 넣어야 한다.** 성공률이 낮은 조건에서는 일찍 끊고
다시 굴리는 것만으로 산술적으로 성공당 토큰이 좋아진다. 이 귀무 정책을
못 이기면 신호가 기여한 것이 없다. (이 교훈은 2026-08-19 분석에서 이미
확인됐다 — 그때 유일하게 이득으로 보였던 조건도 이점 전부가 우연에 걸려
있었다.)

### 오탐 비용을 명시적으로 넣는다

경보 기반 정책의 기대 이득(세션당):

```
이득 = P(실패 | 경보) × R                       ← 아낀 낭비
     − P(성공 | 경보) × (성공 하나를 죽인 비용)   ← 오탐 비용
```

성공 하나를 죽인 비용은 "새 세션의 기대 비용 + 그 세션도 실패할 확률"로
전개한다. 이 항을 빼놓으면 어떤 신호든 좋아 보인다. `RESEARCH_PLAN.md`가
처음부터 요구한 것이다.

## 3. 질문 (c) — 진짜 인과적으로 확인하려면

위 (b)는 근사다. 진짜 답은 **개입 실험**이다.

**설계**: 세션을 돌리다가 경보가 뜨는 순간 무작위로 배정한다.

- 갈래 A: 그대로 계속
- 갈래 B: 즉시 종료하고 새 세션 시작

두 갈래는 **경보 시점까지 완전히 같은 조건**을 공유하므로 비교가 깨끗하다.
배정이 경보 시점에 일어나므로 선택 편향이 없다.

**필요한 것**:
1. 러너가 **조건 충족 시 세션을 중단**할 수 있어야 한다 (현재 없음 —
   `pilot/run_sessions.py`는 끝까지 돌린다).
2. 무작위 배정과 배정 기록.
3. 표본 수 산정 (`pilot/analysis/power.py`).
4. **새 수집이 필요하므로 수집 잠금 해제가 필요하다** (유저 승인 사항,
   `harness/gates.json`).

**언제 해야 하는가**: 지금은 아니다. 현재 과제는 도구 호출 13~19번이면
끝나서 끊어도 아낄 것이 거의 없다(실패 세션의 스텝 8 이후 소비가 전체의
9~31%). **끊는 것이 이득일 수 있는 길이의 과제가 생긴 뒤에** 해야 의미가
있다. 즉 미해결인 과제 설계 문제(`docs/W15_ABILITY_EARLY.md` 1절)가 먼저다.

## 4. 한계 — 미리 적어두는 것

1. **문턱 과적합.** 경보 문턱을 이 데이터로 맞추고 같은 데이터로 평가하면
   부풀려진다. → **조건 하나에서 문턱을 정하고 다른 조건에서 평가한다.**
   기존 데이터로 가능하다(궤도 60세션 / 원장 30세션 / 일정 30세션 /
   ml-shift 7세션이 서로 다른 조건이다).
2. **배치 수준 국면 전환.** 같은 기록상 모델 식별자로 돌린 배치의 성공률이
   33%에서 87%로 바뀐 적이 있다. 재시작 표본을 배치 전체에서 뽑으면 이
   변동에 오염된다. → **시간적으로 가까운 세션에서 뽑고, 민감도를 함께
   보고한다.**
3. **계속 갈래는 세션당 표본이 하나다.** 같은 세션을 여러 번 이어 돌릴 수
   없으므로 계속했을 때의 분포를 세션 하나에서 하나만 얻는다. n으로 메운다.
4. **프롬프트를 고쳐서 재시작하는 경우는 검정되지 않는다.** 실제 사용자는
   그냥 다시 돌리지 않고 지시를 바꿔 다시 돌린다. 우리 비교는 "같은 조건
   재시작"만 다룬다. 한계 절에 명시할 것.
5. **외부 앱은 자동으로 끊지 않는다.** 지렛대는 알림과 종료 권고다
   (`docs/ARCHITECTURE.md`). 따라서 실제 이득에는 사람이 알림을 보고
   판단하는 지연이 끼는데, 이 설계는 그것을 0으로 가정한다. 상한이다.

## 5. 순서

1. 진전 규칙 구현 (`docs/PROGRESS_RULE.md`).
2. 기존 127세션에 경보를 계산 — 시점 τ, 회복률, 경보 이후 소비 R.
   **여기까지가 질문 (a)의 답이고 새 수집이 필요 없다.**
3. 배치 내 재시작 표본으로 정책 비교 — 귀무 정책 둘과 함께.
   **여기까지가 질문 (b)의 답이다.**
4. (a)·(b)가 이득을 보이지 않으면 개입 실험을 하지 않는다. 보이면
   과제 설계 문제를 푼 뒤 (c)로 간다.

3단계까지 전부 수집 잠금을 유지한 채로 할 수 있다.
