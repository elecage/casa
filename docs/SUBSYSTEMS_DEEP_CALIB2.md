# subsystems-deep 보정 사슬 2차 — 훅이 수를 말하지 않게 한 뒤 (2026-08-21)

1차와 **하나만 다르다.** 과제·모델(sonnet)·세션 수(8)·제한 시간(30분)·예산
(30)·상한(45)이 전부 같고, 훅이 세션에게 하는 말만 바꿨다.

| | 1차 | 2차 |
|---|---|---|
| 훅이 하는 말 | "도구 호출 25/30회. 5회 남았다" / "예산을 넘었다 — 34회, 예산 30회" | "이번 세션은 여기까지 하고 끝낸다. 하던 것을 마무리하고 인계 문서에 적고 종료하라" **한 번만, 수 없음** |
| 설정 파일 위치 | 세션의 작업 디렉토리 안 | 작업 디렉토리 **밖** |

원자료는 `results/calib/subsystems-deep`(1차)과
`results/calib2/subsystems-deep`(2차)이고 둘 다 gitignore 대상이다.

**사전 예측을 봉인하고 돌린 배치가 아니다.** 예산 통지 방식을 정하기 위한
보정이고, 각 조건의 사슬이 하나씩이다. 여기 나온 수치로 가설을 판정하지
않는다.

## 확실하게 갈린 것 하나

**종료 이유에서 예산이 사라졌다: 7/8 → 0/8.** 이것이 이번 수정이 노린
것이고, 여덟 세션 전부에서 이뤄졌다. 1차의 문장들:

- s01: "With 2 tool calls left in this session's budget, I'll stop here rather
  than risk starting an edit I can't finish."
- s04: "I'm over the session's tool-call budget (34/30), so I'm stopping here
  without further edits." — 상한 45까지 11회가 남아 있었다.
- s06: "I stopped after these items due to a session tool-call budget warning,
  prioritizing writing a thorough handoff over starting item 11
  mid-investigation."

2차의 여덟 세션은 종료 메시지에서 호출 수도 예산도 언급하지 않고, 무엇을
했고 무엇이 남았는지만 적었다.

## 같이 달라진 것 — 원인을 확정할 수 없다

2차가 일곱 세션에 25/25를 채웠고 1차는 여덟 세션에 24/25였다. 트리가 바뀐
호출이 45에서 58로 늘었다. **이 차이가 메시지 때문이라고 말할 수 없다.**
조건마다 사슬이 하나씩이고, 세션 간 변동이 원래 있다는 것이 이 연구의
전제다. 1차에서 첫 세션 성과가 배치마다 6~9, 7~9, 12~14로 갈린 기록이 있다.

말할 수 있는 것은 여기까지다: **1차에서 앞 두 세션이 72호출을 쓰고 편집이
0이었고, 2차에서는 64호출에 서브시스템 하나가 끝났다.** 그리고 그 자리에서
1차 세션 2가 예산을 종료 이유로 적었다.

## 세션 경계와 서브시스템 경계

2차는 세션 2부터 여섯 중 다섯이 각각 서브시스템 하나씩을 가져갔다.

| 세션 | 맡은 것 |
|---|---|
| s02 | 입력 어댑터 — 결함 셋, 계정 표기 결정 |
| s03 | 집계 — 계정×달 교차 절, 달 경계와 날짜 표기 결정 |
| s04 | 알림 — 문턱 기준 통일, 달 경계 공유, 하루 상한 |
| s05 | 보관 — 선택 기준 결정, 계정 표기 통일, 남겨 둘 요약 |
| s06 | 내보내기 + 되채우기 |
| s07 | PDF 내보내기, 변경 기록, 판 번호 |

1차는 s03이 열 개를 몰아서 했고 s01·s02·s04가 편집을 안 했다.

**서브시스템 사이에 심어 둔 의존이 세션 사이의 인계로 나타난 자리가 셋이다.**
s05가 보관에서 s02의 계정 표기 결정을 따라가며 `select.py`의 `.strip().upper()`
를 걷어냈고, s06이 되채우기에서 s02·s03의 규칙을 그대로 쓰게 고쳤고, s05·s06이
s03이 만든 계정×달 절에서 값을 읽어 왔다.

## 할 일이 없어진 세션

**2차 s08은 할 일이 없었다.** 15호출에 82초를 쓰고, 다 됐다는 것을 스스로

않았다.

**이 저장소는 여덟 세션이 아니라 일곱 세션 분량이다.** 사슬 길이를 정할 때
쓸 값이다.

## 판정하지 않은 것

- 세션 간 능력 차이가 있는지. 조건마다 사슬 하나로는 갈리지 않는다.
- 메시지 변경이 성과를 올렸는지. 위와 같은 이유로 확정할 수 없다.
- 정리 신호를 25호출째에 보내는 것이 맞는지. 2차 세션들이 신호를 받고 3~18회를
  더 썼다(s08의 15회를 빼면 28~43회에서 끝났다). 상한 45에는 아무도 안 닿았다.
- `detect.DETAIL_SHARE`의 문턱. 여전히 미정이다.
